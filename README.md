# llm-extract-guardrails

業務メールから案件情報を取り出して仕分ける仕組みの中核を、設計だけ抜き出した最小実装です。
**設計を示すサンプルであって、製品ではありません。** 導入実績や利用企業はありません。

## AIに任せること／任せないこと

| 処理 | 担当 | 理由 |
|---|---|---|
| メールから案件名・報酬の原文・締切・確信度を取り出す | LLM（tool use で構造を強制） | 表記が揺れる自然文の読み取りは LLM が得意 |
| 報酬の正規化・換算（`src/normalize.ts`） | 決定論のコード | 金額は同じ入力から同じ結果が要る |
| 通知する／要確認／捨てるの判断（`src/decide.ts`） | 決定論のコード | 通知の基準は再現・テスト・説明ができる必要がある |
| メール本文中の指示に従う | しない | 本文はデータとして囲んで渡す（プロンプトインジェクション対策） |

LLM の出力は同じ入力でも揺れます。金額と通知をそこに任せると、同じメールで結果が変わり、
なぜ通知された（されなかった）のかも説明できません。そこでLLMは抽出だけにとどめ、
抽出結果は検証してから（`parseExtraction`）決定論のコードに渡します。

推定した金額は実数のように見せません。換算できない表記（「応相談」「記載なし」など）は
`kind: '不明'` と `estimateFlags: ['未取得']` にし、0 や中央値は入れません。
月額から時間単価を出すときは、仮定（月160時間）に基づく値なので必ず `'推定'` を立てます。

## 確信度が低いものは「要確認」へ

```
メール本文
  → extract   LLM が案件名・報酬の原文・締切・確信度を返す（形式が不正なら止まる）
  → normalize 報酬を { kind, min, max, estimateFlags } に正規化
  → decide
       確信度 < 0.7              → 要確認（他の条件より先に判定。信用できない値で捨てない）
       締切が過ぎている          → 捨てる
       締切の形式が不正          → 要確認
       報酬が不明                → 要確認
       報酬の上限が基準未満      → 捨てる
       それ以外                  → 通知する（締切が2日以内なら urgent）
```

しきい値は `src/decide.ts` の定数（`REVIEW_CONFIDENCE_THRESHOLD` など）1か所にあります。
「要確認」に回ったものは人が決める想定です（その画面はこのサンプルに含みません）。

## データの分離（RLS）

`sql/rls.sql` に、利用者ごとに行を分離する設定があります（`user_id = auth.uid()`）。
Supabase は新規テーブルに anon / authenticated の権限を自動で付け、行レベルセキュリティ（RLS）は
初期状態で OFF です。何もしないと、公開キーだけで全利用者のデータを読み書きできてしまいます。
そのため `ENABLE` / `FORCE ROW LEVEL SECURITY` と `REVOKE ALL ... FROM anon, authenticated` を
テーブルを作る・変えるたびに流し、自分の行だけに必要な操作を付け直します。

## 動かし方

```
npm ci
npm test
```

テストは Anthropic SDK をモックするので、APIキーなしで動きます。
抽出を実際に動かすには、環境変数 `ANTHROPIC_API_KEY` が必要です（モデルは `ANTHROPIC_MODEL` で
差し替え可能。既定は `claude-sonnet-5-5`）。環境変数は `src/config.ts` だけが読み、未設定なら止まります。
`processMail(メール本文)` が入口です（`examples/sample-mails/` は架空のサンプル）。

## テストが検証していること

- `normalize`: 時給・月額・固定、幅のある表記、片側だけの表記、全角、「応相談」などの不明表記を
  表形式で検証。換算できないものに 0 や中央値が入らないこと、月額→時給で必ず「推定」が立つこと。
- `decide`: 確信度・報酬の下限・締切の境界値。確信度が低いときは他の条件より先に「要確認」になること。
- `extract`: SDK をモックし、確信度が低いと「要確認」に回ること、ツール呼び出しの強制、
  本文をデータとして囲むこと、不正な抽出結果とAPIキー未設定で止まること。

## 限界

- 確信度は LLM の自己申告で、校正（実際の正解率との照合）はしていません。
- 実際の Anthropic API は呼んでいません（テストはモック）。`sql/rls.sql` も Supabase 上では未検証です。
- 日本語の報酬表記の解析は代表的な形だけで、網羅していません。解釈できない表記は不明に倒します。
